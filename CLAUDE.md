# CLAUDE.md

Creative fatigue flagger for Meta ads: React + Vite + TypeScript UI, Vercel functions for the JSON API and MCP server, vitest tests.

## Commands
- `npm run dev`: UI plus `/api/*` (served by a Vite middleware in `vite.config.ts` that calls the same handlers as Vercel)
- `npm test`: run all tests. Run this after every logic change.
- `npm run build`: `tsc -b` + Vite build. Must pass before committing.

## Architecture rules
- `lib/fatigue.ts` is the only place the flagging rules live. The UI, `/api/flag` and the MCP tool all call `flagFatiguedCreatives`. Never re-implement CTR math anywhere else.
- `lib/handlers.ts` exports web-standard `(Request) => Response` handlers. `api/*.ts` files only re-export them. Keep them dependency-free.
- Relative imports inside `lib/` and `api/` use `.js` extensions (needed for Node ESM on Vercel). The UI imports without extensions.
- Status labels are exactly: `flagged`, `ok`, `too new to judge`, `not enough volume`. They are part of the public API.

## Domain rules (from the challenge brief)
- Baseline CTR = sum(clicks)/sum(impressions) over the creative's first 7 days with impressions > 0.
- Current CTR = the same over the last 7 calendar days of the file (one shared window for all creatives).
- drop = 1 - current/baseline; flag when drop >= threshold (default 0.3, compare with 1e-9 tolerance).
- Fewer than 14 delivering days: "too new to judge". Under 5,000 impressions in the last 7 days: "not enough volume". Check in that order.
- Zero-impression days are pauses, not data: they never enter the baseline, the age count, or the sparkline line.

## Testing
- Every new edge case gets a test in `tests/fatigue.test.ts` built with the `csv()` and `repeat()` helpers.
- `public/demo-data.csv` is generated by `scripts/make-demo-data.py`. If you change it, update the expected statuses in the "demo data" test.
