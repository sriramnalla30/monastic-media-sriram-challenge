# Creative Fatigue Flagger

Monastic Media AI Engineer fast-track challenge, by Sriram Nalla.

Upload daily Meta ad performance data and see which creatives have **lost 30% or more of their baseline CTR**. The same logic is available as a web app, a JSON API and an MCP tool.

## The rule

| Term | Definition |
| --- | --- |
| Baseline CTR | Total clicks ÷ total impressions over the creative's **first 7 days with impressions > 0** |
| Current CTR | Total clicks ÷ total impressions over the **last 7 calendar days of the file** |
| Drop | `1 − current / baseline` |
| **flagged** | drop ≥ threshold (default 30%, configurable) |
| **too new to judge** | fewer than 14 days with delivery |
| **not enough volume** | under 5,000 impressions in the last 7 days |
| **ok** | everything else |

### Decisions I made where the brief left room

1. **CTR is impression-weighted** (sum of clicks ÷ sum of impressions), not the average of daily CTRs, so one 200-impression day can't swing the baseline.
2. **A pause is not data.** Days with 0 impressions, or with no row at all, don't count toward the baseline or toward the 14-day age. Sparklines show them as gaps.
3. **"Last 7 days in the file" is one shared window** that ends on the file's last date, so every creative is compared over the same week. A creative paused all week has 0 impressions there and is "not enough volume".
4. **"14 days" means 14 days with delivery.** A late launch or a paused creative isn't judged until it has really run for two weeks, and its baseline is its own first 7 delivering days.
5. **Check order:** too new → not enough volume → drop. A creative must be judgeable before its drop can count.
6. **Exactly at the threshold is flagged** (with a 1e-9 tolerance so `1 − 0.7` float noise doesn't decide the result).
7. **A baseline with zero clicks** can't drop, so it's "ok" with no drop value instead of dividing by zero. A collapse to 0 clicks is a 100% drop.
8. **Messy input doesn't crash:** quoted fields with commas, a BOM, columns in any order or case, and duplicate ad/date rows (summed) are all handled. Bad rows are skipped and listed as warnings.

## Use it

### Web app
Upload a CSV, paste a CSV URL (the Monastic Media sample URL is pre-filled), or click **Try demo data**. The threshold slider and impressions floor recompute instantly in the browser.

`public/demo-data.csv` is generated by `scripts/make-demo-data.py` and has one creative per edge case: steady, fatiguing, paused mid-month, late launch, low volume, dipped and recovered, paused last week, just over the threshold, just under it, and late launch then fatigued.

### JSON API
```bash
# CSV by URL
curl "https://<your-app>/api/flag?csv_url=https://api.monastic.media/functions/v1/careers-mcp/challenge/sample-data.csv&drop_threshold=0.3"

# CSV in the body
curl -X POST "https://<your-app>/api/flag?drop_threshold=30" -H "content-type: text/csv" --data-binary @data.csv

# JSON body
curl -X POST https://<your-app>/api/flag -H "content-type: application/json" \
  -d '{"csv_url": "https://.../data.csv", "drop_threshold": 0.3, "min_impressions": 5000}'
```
`drop_threshold` takes a fraction (`0.3`) or a percent (`30`). Bad input returns HTTP 400 with a readable `error`.

### MCP tool
The endpoint `https://<your-app>/api/mcp` is a stateless Streamable HTTP MCP server with one tool, `flag_fatigued_creatives(csv_url, drop_threshold, min_impressions?, include_daily?)`.

```bash
claude mcp add --transport http fatigue-flagger https://<your-app>/api/mcp
```
Then ask: *"Which creatives in https://…/sample-data.csv are fatigued?"*

## Run locally

```bash
npm install
npm run dev        # app + /api/flag + /api/mcp on http://localhost:5173
npm test           # 34 unit tests (vitest)
npm run build      # typecheck + production build
```

## Layout

```
lib/fatigue.ts     the pure flagging logic (single source of truth)
lib/csv.ts         RFC 4180 CSV parser
lib/handlers.ts    JSON API, CSV proxy and MCP server as Request -> Response handlers
api/*.ts           Vercel functions that export those handlers
src/               React + Vite UI (sparklines are hand-drawn SVG, no chart library)
tests/             vitest suite: CTR math, edge cases, input handling, API and MCP
CLAUDE.md          instructions for the AI coding agent
prompts/           the prompts used to build this
```

## Deploy (Vercel, free)

Import the GitHub repo at vercel.com/new. `vercel.json` sets the Vite framework, and the `api/` folder becomes serverless functions automatically. No environment variables are needed.
